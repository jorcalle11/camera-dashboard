# web-app

React + Tailwind client for the camera dashboard. Mobile-first, two tabs:

- **Live** — grid of live tiles streamed from go2rtc (WebRTC first, MSE
  fallback). Offscreen tiles pause to a still poster; click a tile for
  fullscreen. Recorder status badges come from the server's `/api/ws`
  WebSocket.
- **Timeline** — per-camera playback: date picker, zoomable 24h strip showing
  recorded coverage, scrubbing, skip, and 1x/2x/4x speed. Video plays through
  hls.js against the server's HLS VOD endpoint.

Light/dark theme with a manual switcher (`useTheme` / `ThemeSwitcher`).

## Layout

```
public/cameras.json   # GENERATED by cameras-setup — never edit by hand
src/
├── components/       # LiveGrid, CameraTile, VideoStream, TabBar, TileOverlay,
│                     #   TimelinePage, TimelineStrip, PlaybackPlayer,
│                     #   TransportBar, DateSelect, CameraSelect, ThemeSwitcher
├── hooks/            # useCameras, useRecorderStatus, useRecordingsSummary,
│                     #   useTheme, useToast
└── lib/              # go2rtc.ts (stream URLs + web component loader),
                      #   timeline.ts, vodPlaylist.ts
```

## Development

Runs as a Vite dev server inside Docker via the repo root compose file
(`vite --host` on :5173). Vite proxies:

- `/go2rtc` → go2rtc API (WebSocket-aware; rewrites the `Origin` header —
  go2rtc 403s upgrades whose Origin doesn't match its host)
- `/api` → server (includes `/api/ws` and `/api/statics/recordings`)

Proxy targets come from `GO2RTC_URL` / `SERVER_URL` env vars (default to
`localhost` when running Vite directly on the host).

```bash
docker compose up -d web-app
docker compose run --rm web-app npm test   # vitest + jsdom
```

## Production

Not shipped as its own image: the `nginx/` image builds this package
(`vite build`) in a multi-stage build and serves the static bundle, with
nginx handling the `/api` and `/go2rtc` proxying that Vite does in dev.
